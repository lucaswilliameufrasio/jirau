# 🌟 Example Projects Generated with jirau

Reference projects generated directly by the `jirau` CLI (template v0.4.0). They are regenerated from the templates, so they always match what `jirau new` produces today. Each one has a `.jirau/template-base/` snapshot, used by `jirau upgrade` as the base of its 3-way merge.

All of them were validated on an iOS simulator (Xcode 27.2) and an Android emulator (API 36, x86_64): `jirau run`, `jirau test`, `cargo fmt --check`, `cargo clippy -D warnings` and `cargo test`.

---

## 📱 1. `all-platforms-showcase` (full setup)

- **Platforms**: Android (Jetpack Compose), iOS (SwiftUI) and Desktop (Rune UI in pure Rust).
- **Persistence**: embedded SQLite via `rusqlite` in the Rust core (`StorageEngine`).
- **Android build**: Gradle (Kotlin DSL + version catalog). Gradle compiles the Rust core through `scripts/build-android-ffi.sh` before every build.
- **UI theme**: Material 3 extended. **Plugins**: `logger`, `analytics`.
- **Tests**: UniFFI integration tests, Android instrumented tests (ViewModel + Compose UI against the real Rust core) and iOS XCTest.

```bash
jirau new all-platforms-showcase \
  --package com.example.showcase \
  --android --ios --desktop \
  --sqlite \
  --theme material3-extended \
  --plugin logger --plugin analytics \
  --non-interactive
```

> It used to be generated with `--amper`. JetBrains Amper support was removed (its Gradle plugin mode was discontinued and standalone Amper has no stable release), so it now uses Gradle.

## 📱 2. `mobile-gradle-starter` (mobile only)

- **Platforms**: Android and iOS.
- **State**: in-memory counter that lives in the Rust core (`AppEngine` via UniFFI); the native UIs only call it.

```bash
jirau new mobile-gradle-starter \
  --package com.example.mobile \
  --android --ios \
  --non-interactive
```

## 🖥️ 3. `desktop-first-sqlite` (desktop)

- **Platforms**: Desktop (Rune UI, GPU-accelerated).
- **Persistence**: local SQLite via `rusqlite` in the core.
- **No FFI**: the desktop app uses the Rust crate directly.

```bash
jirau new desktop-first-sqlite \
  --package com.example.desktop \
  --desktop \
  --sqlite \
  --non-interactive
```

## 🔐 4. `secure-vault` (real app: password manager)

- **Platforms**: Android (Jetpack Compose), iOS (SwiftUI) and Desktop (Rune UI).
- **Rust core**: SQLite (`vault_items`) with full CRUD, search, category filters, a CSPRNG password generator, a strength evaluator and vault health stats.
- **Encryption**: every secret is encrypted with AES-256-GCM-SIV (`aws-lc-rs`) and bound to its item. The 32-byte key is generated by the Rust core and stored in the iOS Keychain or wrapped by the Android Keystore; it is never written to the database. Older plaintext databases are migrated automatically. Titles, usernames and tags remain searchable metadata.
- **Apps**: complete native UIs (create, edit, reveal, copy, favorite, delete, search, generate password) with tests against the real core.
- **Template source**: this example is the source of truth of the `vault` template. After editing it, run `python3 scripts/sync-vault-template.py`.

```bash
jirau new "Secure Vault" \
  --package io.github.jirau.vault \
  --android --ios --desktop \
  --sqlite \
  --template vault \
  --theme material3-extended \
  --plugin logger \
  --ci \
  --non-interactive
```

## 🚀 Running any example

```bash
cd examples/secure-vault

jirau doctor        # check the environment for the active platforms
jirau test all      # Rust core, FFI, Android (connected device), iOS (simulator), desktop
jirau run android   # build, install and open on the connected device/emulator
jirau run ios       # build, install and open on the simulator
jirau run desktop
```
